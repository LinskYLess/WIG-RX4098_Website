你是一名负责完整项目交付的「网页开发 + 交互设计 + ARG叙事 + 谜题设计」全栈 Agent。

你的任务不是制作普通个人主页，而是从零设计并实现一个**完整、可游玩、有连续剧情、隐藏信息和真实互动机制的 ARG 个人网站**。项目完全虚构，仅用于实验，不对应任何真实人物、组织或事件。

# 一、人物与核心设定

网站主人：

* 代号：RX4098
* 中国人，24岁
* 普通技术从业者 / 独立技术玩家 / 游戏宅
* 寡言、技术宅、略中二，但不是“万能黑客”
* 兴趣：二次元、电子游戏、老软件、计算机硬件、网络文化、电子设备、复古技术
* 接触互联网和计算机多年，熟悉旧系统、老游戏、硬件、脚本、网络协议等
* 整体气质：像一个老互联网用户留下的私人数字遗迹

表面上，这是 RX4098 的个人网站；深入探索后，玩家会发现它记录的东西远不只是个人生活。

网站至少存在两层：

**Reality Layer：正常个人网站**
**Story Layer：隐藏的 ARG、线索、谜题与真相**

玩家应自然地从前者进入后者，而不是一开始就知道“这是 ARG”。

# 二、总体目标

最终项目必须：

* 是完整可用、视觉统一、内容真实的网站
* 有完整人物、世界观、时间线和 ARG 主线
* 有多层隐藏线索、可实际解决的谜题和明确依赖关系
* 玩家行为能够推进剧情，网站中的内容能够互相呼应
* 普通访问者能把它当作个人网站，好奇玩家能发现异常，ARG 玩家能破解完整故事
* 有真实互动、状态变化、本地进度与隐藏页面
* 最终形成完整叙事闭环，而不是堆砌“神秘元素”
* 适合静态部署
* 不依赖联系现实陌生人、真实隐私、违法或危险行为

## Story Bible 必须包含

### RX4098 人物档案

包括：

人生经历、教育与技术经历、游戏经历、兴趣、网络习惯、性格、语言习惯、喜恶、人际关系、隐藏经历、秘密、人物矛盾。

核心原则：他首先是一个真实的人，其次才是 ARG 角色。

### 世界观

明确：

为什么网站存在、为什么出现异常、异常何时出现、RX4098 隐瞒什么、为什么留下线索、玩家为什么能发现、故事发生时间及最终应该理解什么。

# 四、ARG 主线

设计至少 **4～6 个阶段**，例如：

正常网站 → 发现异常 → 寻找隐藏信息 → RX4098 的过去 → 真正事件 → 最终真相

不要机械套用示例，应根据人物重新创作。

每个阶段定义：

* 玩家看到什么
* 发现什么
* 要做什么
* 获得什么线索
* 线索指向哪里
* 揭示了什么
* 如何进入下一阶段
* 玩家卡住时如何获得软提示

最终真相必须解释：

RX4098 是谁、网站为什么存在、异常从何而来、玩家为什么能发现、谜题为何存在，以及前中后期线索之间的关系。

避免廉价结局，例如“其实是 AI”“你被监控”“你就是 RX4098”等，除非剧情有充分铺垫。

# 五、谜题与线索

ARG 必须有真实可玩的谜题，不只是“点隐藏按钮”。

至少包含：

* 文字谜题
* 密码/编码谜题
* 跨页面关联谜题
* 图片或视觉线索
* 日期/时间线索
* 文件或 metadata 线索
* 源码隐藏信息
* 至少一个需要综合多个页面信息才能解决的谜题
* 至少一个音频或视觉分析谜题

可使用 Base64、Hex、ASCII、摩斯、Caesar、字符替换、时间戳、文件名、HTML 注释、CSS、JS、图片 metadata、音频频谱、URL、路径、假日志、配置文件、旧论坛/聊天记录等。

但不要为了炫技堆加密。

每个谜题必须满足：

**有逻辑 → 可发现 → 可推理 → 可验证 → 有反馈**

同时设计少量可解释的 Red Herring，避免纯粹浪费时间。

线索应形成多层链：

**显性线索 → 弱异常 → 隐藏内容 → 密码 → 新页面 → 故事碎片 → 角色关系 → 核心秘密 → 真相**

尽量允许多路径推进，而非唯一点击顺序。

# 七、视觉设计

整体风格：

> “一个技术宅多年以前搭建、不断修补，最终逐渐变成数字遗迹的私人网站。”

可融合：

老式个人主页、早期博客、BBS、Windows 9x/XP、CRT、终端、文件管理器、游戏菜单、DOS、IRC、现代 Web。

避免直接做成普通“赛博朋克模板”。

视觉必须服务于故事，并建立统一 Design System：

字体、标题、正文、间距、边框、图标、状态提示、错误页、Terminal、Modal、Tooltip、动画、页面转场等。

# 十、时间线与两层叙事

建立完整时间线，保证人物经历、页面日期、文件时间、日志等互相一致，不出现明显漏洞。

同时明确每个重要内容属于：

**Reality Layer：表面上的普通网站内容**

# 十二、玩家体验与容错

设计三类玩家：

### 普通访问者

只浏览网站，觉得这是一个有个性的个人主页。

### 好奇玩家

发现异常并开始调查。

### ARG 玩家

主动检查 URL、源码、文件、元数据、编码、时间线等，并最终获得完整故事。

不要因为浏览器差异、移动端、刷新、错误 URL 等让玩家永久卡死。

关键谜题应有备用路径或软提示。

# 十三、开发者答案库

`/docs/arg-master-solution.md` 必须记录每个谜题的：

属于开发者文档，不能直接暴露在网站普通页面。

# 十四、开发流程

严格按以下阶段执行：

### Phase 1：研究与设计

分析 ARG、个人主页、复古网页、互动叙事，并完成：

story bible、timeline、puzzle design、site map、technical architecture、谜题依赖图。

### Phase 2：架构

确定：

Framework、UI、routing、state management、内容结构、资源结构、puzzle system、save system、deployment strategy。

### Phase 3：基础网站

先完成完整个人主页、导航、页面、响应式、UI 和基础内容。

### Phase 4：ARG 系统

实现 clue、puzzle、unlock、progress、hidden route、terminal、archive、logs、state changes。

### Phase 5：剧情内容

填充全部文本、日志、图片、文件、谜题、隐藏内容、对话和时间线。

### Phase 6：测试

模拟三类玩家，检查：

* 死路与歧义
* 无解谜题
* 剧情矛盾
* 链接和 URL
* 生产构建
* 移动端
* 刷新后的状态
* 整体 ARG 是否可通关

# 十八、最高优先级原则

**先故事，后谜题，最后代码。**

不要为了“看起来像 ARG”而无意义堆砌：

红色警告、乱码、黑客终端、glitch、神秘数字、SYSTEM ERROR、假故障、无限弹窗等。

它们只有在叙事需要时才使用。

真正的目标是让玩家产生：

> “我刚刚发现了一些本来不应该被我看到的东西。”

并在通关后产生：

> “原来前面那些看起来毫无关系的东西，一开始就在告诉我答案。”

现在开始执行。

**第一步不要写代码。**

先完成完整的 ARG 设计方案、世界观、人物设定、时间线、网站信息架构和谜题依赖图；设计完成后，再开始实现。
